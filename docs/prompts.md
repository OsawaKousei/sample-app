# Codexへの指示例

「目的・対象・完成条件・確認方法」を伝えます。APIキーや `.env` の中身は貼り付けません。一度にすべてを作らず、小さな変更を確認しながら進めます。

## コードの流れを読む

```text
README.mdとdocs/architecture.mdを読み、TODOの追加ボタンからSQLiteへ
保存されるまでの流れを、ファイル名と関数名を挙げて説明してください。
この段階では変更しないでください。
```

## ダッシュボードを改造する

```text
TODOダッシュボードを、青を基調とした落ち着いた配色にしてください。
優先度の高いカードは文字と色で見分けやすくしてください。
TodoCard.tsxとstyles.cssを中心に、操作方法を保って変更してください。
390px幅とキーボード操作を確認し、npm run checkを実行してください。
```

## APIを追加する

```text
GET /api/todos/importantを追加し、priorityがhighであるTODOだけを
SQLiteから取得してください。App.tsxに「重要なTODO」表示を追加し、
新しいAPIから取得して表示してください。既存の表示切り替えも保ちます。
一時DBを使ったテストを追加し、npm run checkを実行してください。
```

## オリジナルアプリの仕様を整理する

```text
docs/original-app-template.mdを参考に、読書記録アプリの仕様を整理したいです。
利用者は自分一人で、ローカル実行を想定します。
最初は本の登録・感想・一覧表示に絞りたいです。
必要な画面とデータ項目、完成条件を提案し、曖昧な点を確認してください。
まだ実装は始めないでください。
```

## 計画から小さく実装する

```text
合意した仕様から、画面・共通型・API・DB・確認の実装タスクを作ってください。
既存データを保持し、Windows/macOSでnpm installとnpm run devが使える構成にします。
最初のタスクだけを実装し、変更点と動作確認の方法を説明してください。
```

## エラーを調べる

```text
期待する動作：TODOを保存すると一覧に追加される。
実際の動作：ここに状況を書く。
再現手順：ここに操作を書く。
環境：OSとnode --versionを書く。
エラー：秘密情報を除いたエラーを書く。
原因を調べ、修正して同じ操作とnpm run checkで確認してください。
```

## 差分を確認する

```text
git diffを確認し、型・画面・API・DBの不一致、既存データへの影響、
通信失敗時の入力保持、画面幅とキーボード操作を確認してください。
問題があれば修正し、必要なチェックを実行してください。
```
