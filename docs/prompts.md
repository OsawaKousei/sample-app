# Codexへの指示例

基本は「目的」「対象」「完成条件」「確認方法」を具体的に伝え、小さな変更を重ねます。変更後は差分と実際の画面を自分でも確認します。秘密情報を含む `.env` を添付しません。

## まず構成を理解する

```text
README.mdとdocs/architecture.mdを読み、
カードを作成してからSQLiteに保存されるまでの流れを、
ファイル名・関数名を添えて初心者向けに説明してください。
この段階ではコードを変更しないでください。
```

## 見た目を変える

```text
このアプリを旅行アイデアのメモに使いたいです。
App.tsxの見出し・説明・空状態の案内を旅行向けに変更し、
styles.cssで落ち着いた青系のテーマにしてください。
カードの作成・編集・削除・検索がそのまま動き、
390px幅でもボタンと文字がはみ出さないようにしてください。
変更後に型チェックを実行してください。
```

## 項目を追加する

```text
カードにauthor（著者名、空文字可、100文字以内）を追加したいです。
共通型、既存SQLiteの移行、APIの入力チェックとCRUD、
フォーム・カード表示・検索を一通り更新してください。
既存カードは著者名が空でも開けるようにしてください。
保存・更新・不正入力・既存DBの互換性を確認し、npm run checkを実行してください。
```

## AI機能を変える

```text
読書メモから、次に考えたい問いを3つ提案するAI機能にしたいです。
ai.tsのプロンプトとモック応答、画面の説明を用途に合わせて更新してください。
Responses APIを使う構成、キーをサーバーだけで読む構成、
回数制限・トークン上限・AI失敗時のCRUDを維持してください。
生成結果を再読み込み後も表示できることを確認してください。
```

## エラーを調べる

```text
期待する動作：カテゴリを選ぶと、そのカテゴリだけ表示される。
実際の動作：選んでも全件表示される。
再現手順：起動 → 「学び」をクリック → 一覧を見る。
環境：OSとnode --versionの結果をここに記載。
秘密情報を含まないエラー本文：ここに記載。
原因を調べ、必要な箇所を修正して、同じ操作で再確認してください。
```

## 変更を見直す

```text
今回のgit diffを確認し、意図しない変更、APIと型の不一致、
既存データへの影響、キーボードで操作できない箇所がないか調べてください。
問題があれば具体的な再現条件と修正を示し、適切なチェックを実行してください。
```

大きな依頼を出した場合も、保存→画面→再起動の順に確かめます。うまくいかないときは「動かない」だけでなく、期待・実際・再現手順を伝えると調査しやすくなります。
