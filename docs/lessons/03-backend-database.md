## ハンズオン：通信を見る

1. ブラウザーの開発者ツールでNetworkを開く。
2. 新しいカードを保存し、`POST /api/cards` のリクエストと201応答を見る。
3. 編集時のPUT、削除時のDELETEと204を確認する。
4. 別タブで http://127.0.0.1:3000/api/cards を開き、JSONを見る。
5. `api/app/src/app.ts` の対応するルートと `database.ts` のSQLを探す。

APIはタイトル1〜120文字、説明4,000文字までを受け付けます。フォームの制限だけでなく、APIにも検証が必要な理由を考えます。

## 共通課題：優先度を追加する

まず停止し、`.local` フォルダを別名でコピーしてDBをバックアップします。実験でデータを失わないよう、既存DBを削除せず移行する課題です。

```text
カードにpriority（low / medium / high、初期値medium）を追加してください。
shared/board.ts、SQLite、APIの入力チェックとCRUD、Reactのフォーム・表示を更新してください。
既存DBはPRAGMA table_info(cards)で列を確認し、存在しないときだけ
ALTER TABLE cards ADD COLUMN priority TEXT NOT NULL DEFAULT 'medium' を実行してください。
既存カードとサンプルデータにも初期値が入り、再起動しても移行が重複しないようにしてください。
古いクライアントがpriorityを省略した場合はmediumとして扱ってください。
追加項目の保存・更新・不正値の拒否を自動テストで確認し、npm run checkを実行してください。
```

このサンプルの `CREATE TABLE IF NOT EXISTS` だけでは既存テーブルに列は追加されません。既存DBと、新しく作るテストDBの両方で確認することがポイントです。

## 自由改造

優先度を使って絞り込む、読書ボードに著者名を追加する、旅行ボードに予算を追加する、などから1つ選びます。まずデータの型・初期値・入力範囲を紙に書き、同じ手順で進めます。

## 確認と完了条件

- 改造前に保存したカードを開ける。
- 優先度を指定して作成・変更できる。
- サーバー停止・再起動・ページ再読み込み後も値が残る。
- 不正な優先度はAPIが拒否し、画面にエラーが出る。
- `npm run check` が成功し、変更したコードをコミットできる。

DBを調べるときはNode.jsの `node:sqlite` が使えます。講師に読み取りスクリプトを作ってもらうか、Codexに「DBを書き換えず、cardsテーブルの定義と先頭5件を表示するスクリプトを作って」と依頼します。実データやキーをチャットに貼らないでください。
