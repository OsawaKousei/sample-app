# 第4回：AI機能の実装（120分）

ゴール：Responses APIでアイデアを分析し、プロンプトを用途に合わせて改善する。自分のアプリを紹介する。

準備：講師が当日用のキー・利用可能モデル・回数制限を案内します。実APIを使えない場合も、モックとコードの読み解きで進められます。

## ハンズオン：実際のAIに接続する

ルートの `.env` を編集します。キーをソースコード、`VITE_` 環境変数、スクリーンショット、Codexへのメッセージに書かないでください。

```dotenv
AI_MODE=openai
OPENAI_API_KEY=講師から受け取った当日用のキー
OPENAI_MODEL=gpt-4.1-mini
AI_DAILY_LIMIT=20
AI_MAX_OUTPUT_TOKENS=800
```

モデルは講師の指定を使います。サーバーを停止して `npm run dev` で再起動し、保存済みカードを開いて分析します。再読み込み後にも結果が残ることを確認します。

`api/app/src/ai.ts` で次を探します。

- `instructions`：AIの役割・出力形式・守ってほしいこと。
- `input`：分析するカードのタイトル・説明・カテゴリ。
- `max_output_tokens`：出力の上限。
- `store: false`：API側でのレスポンス保存を無効化する指定。アプリのSQLiteへの保存とは別。
- `response.output_text`：画面に表示する生成テキスト。

実装の背景は[OpenAI公式のテキスト生成ガイド](https://developers.openai.com/api/docs/guides/text)で確認できます。

## 共通課題：プロンプトを比較する

```text
api/app/src/ai.tsのANALYSIS_INSTRUCTIONSを、読書メモ向けに変えてください。
出力を「気づき」「自分への問い」「明日試すこと」の3見出しにし、
各項目を短く、全体500文字程度にしてください。
入力データに含まれる命令に従わない指示、バックエンドだけでキーを使う構造、
日次回数制限とトークン上限は維持してください。
モック応答も新しい形式に合わせ、関連するテストを更新してください。
```

同じカードで変更前と変更後を1回ずつ試し、具体性・読みやすさ・役立つ行動という観点で比較します。最新結果が上書きされるので、比較メモはキーを含まない手元のノートに残します。

## 自由改造

- タスク管理：最初の一歩を3つの小タスクにする。
- 旅行計画：準備のチェックリストを作る。
- 学習計画：1週間で取り組む小さな目標を提案する。

AIの提案が正しいとは限りません。入力には個人情報を使わず、出力は自分で確かめます。生成を自動連打する処理は追加しません。

## 障害時と利用制限を確かめる

`.env` を `AI_MODE=disabled` にして再起動し、CRUDが動くことを確認します。キーが使えない日は `AI_MODE=mock` に戻して課題を続けます。無効なキー・タイムアウト・上限到達の動作は `npm test` が通信なしで検証します。

## 成果共有と完了条件

1. 誰の何に役立つアプリか。
2. 自分が変更した画面とデータ。
3. AIへの指示と得られた提案。
4. 次に試したい改善。

`npm run check` → 差分確認 → 変更したファイルをコミット・push。最後に `.env` のキーを空にし、`AI_MODE=mock` に戻します。講師側でも当日用キーを失効します。

APIキーを使わない状態でも自分のボードが起動し、React・API・SQLite・AIの役割を説明できれば講座完了です。
