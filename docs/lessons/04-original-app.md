# 第4回：オリジナルアプリ開発（120分）

テーマ：自分のアイデアをWebアプリにしてみよう。

ゴール：目的と利用者を整理し、仕様検討・実装計画・実装・検証の流れを体験します。成果物はローカルで動くアプリと、その仕様・実装計画です。

## 時間配分

| 内容 | 時間 |
| --- | ---: |
| オリジナルアプリ開発の進め方 | 15分 |
| アイデア整理・仕様検討 | 25分 |
| 実装計画の作成 | 15分 |
| Codexによる実装 | 40分 |
| 成果共有 | 15分 |
| 対象範囲・セキュリティ上の注意の再確認 | 10分 |
| 合計 | 120分 |

## 1. アイデアを考える

読書記録、旅行の準備、学習ノート、献立メモなど、自分が使いたい場面を一つ選びます。「誰が・いつ・何をするために使うか」を一文にします。最初から多くの機能を盛り込まず、中心となる操作を決めます。

## 2. ChatGPT・Codexと仕様を整理する

[仕様・実装計画テンプレート](../original-app-template.md) をコピーし、目的、利用者、必要な機能、作らない機能、画面、データ項目、完成条件を書きます。

```text
自分用の読書記録アプリを作りたいです。ローカルで動かします。
本の登録、感想の記録、読んだ本の一覧が欲しいです。
画面とデータ項目、完成条件を一緒に整理してください。
初心者が40分程度で試せる小さな構成に絞り、まだ実装はしないでください。
```

AIの提案をそのまま採用せず、本当に必要な機能かを判断します。AI機能は必要な場合だけ使います。

## 3. 実装計画を作る

共通型 → DB・API → 画面 → 必要ならAI → 確認、という小さなタスクへ分けます。各タスクに対象ファイルと確認方法を書きます。既存アプリを改造する場合はデータを引き継ぐ方法も決めます。

```text
合意した仕様をもとに、対象ファイルと確認方法を含む実装計画を作ってください。
Windows/macOSでnpm installとnpm run devが使える構成を保ちます。
既存DBは消さず、必要な変更はデータを保持して移行します。
```

## 4. Codexで段階的に実装する

変更前にコミットとDBのバックアップを行います。一つのタスクを依頼し、差分と動作を確認してから次へ進みます。期待と違う場合は「期待する動作・実際の動作・再現手順」を伝えて修正します。

- 登録した内容が一覧に表示されるか。
- 編集や削除が意図どおりか。
- 再起動後もデータが残るか。
- AIや通信が失敗したとき、状況が分かるか。
- `npm run check` が成功するか。

## 5. 成果を共有する

目的と利用者、できた操作、工夫した点、未完成の点を紹介します。仕様・実装計画とソースをGitHubへ記録し、`.env` やDBが含まれていないことを確認します。

## 6. 講座の振り返り

学んだことは、Codexを使った開発、画面の改造、APIとDBの変更、仕様検討、計画、実装、検証です。インフラ、デプロイ、認証、監視、バックアップ運用、公開に必要なセキュリティの実装・検証は扱っていません。

ローカルで動くことと、安全に公開できることは別です。公開する場合は認証・認可、不正アクセス、入力検証、XSS・SQLインジェクション、機密情報、APIの利用料金、データ保護、ライブラリの脆弱性、本番設定などを別途確認します。Codexが作ったコードにも検証が必要です。

APIキーはソースやReactへ記述せず、GitHubへアップロードしません。漏洩したキーは速やかに無効化・再発行します。
