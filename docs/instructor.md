# 講師向け準備・運営

## 講座前

- 要件は `docs/spec.md`。全4回、各120分で、毎回共通課題と自由改造を含みます。
- Windows / macOSの実機で、Node.js 24.13以降・Git・VS Code・Codexの導入から起動まで事前確認します。
- 自分のGitHubリポジトリに教材を置き、Forkまたはテンプレートとして参加者へ案内します。
- `npm ci` → `npm run check` → 画面で作成・編集・検索・削除・モック分析を確認します。
- APIキーなしで第1〜3回を進められるよう、配布物に `.env` や `.local` を含めず、`.env.example` を使います。
- 各回の課題を試し、特に第3回は既存DBへの項目追加を確認します。
- コミット済みの解答例や講師用ブランチを用意する場合、参加者の作業を上書きしない配布方法を案内します。

## 第4回のOpenAI API利用環境

このリポジトリはアプリとローカル制限を提供します。実際のプロジェクト作成・支払い・当日用認証情報の発行・失効は、講師のOpenAIアカウントで行います。

1. 講座用プロジェクトを分け、利用モデルと参加人数に合う予算・レート制限を決める。
2. 各参加者の開発用プロジェクトキー、または運営ポリシーに沿う参加者単位の認証情報を準備する。個人の常用キー・管理用キーを共有しない。
3. 当日のみ使う認証情報は参加者ごとに安全な経路で渡し、可能な場合は期限も設定する。
4. 当日のプロジェクトでResponses APIと指定モデルが使えることを、実キーで少数回確認する。`.env.example` のモデル名は設定例なので必要なら配布前に変更する。
5. プロジェクトのLimitsで通知と、利用可能なハード支出上限を確認する。通知だけでは通信は停止しない。ハード上限も反映遅延による小さな超過があり得るため、余裕を持って設定する。
6. 参加人数×許容回数×入出力トークンの目安で運営予算を見積もり、当日も使用状況を確認する。価格は固定値を教材に埋め込まず当日の公式価格を参照する。
7. 講義終了時刻に講師がキーを失効する担当と手順を決める。アプリ内の設定だけでは当日限定を強制しない。

認証情報の扱いは[公式のAPIキーとサービスアカウント](https://developers.openai.com/api/docs/guides/api-keys)、支出上限は[公式のSpend limits](https://developers.openai.com/api/docs/guides/spend-limits)を参照してください。画面・権限・提供機能は当日のプロジェクトで確認します。

## アプリ内の利用制限

| 項目 | 既定値・動作 |
| --- | --- |
| モード | `mock`。外部通信なし |
| 日次実API試行回数 | `AI_DAILY_LIMIT=20`、UTC日付、SQLiteに保存 |
| 入力上限 | タイトル120文字、説明4,000文字 |
| 出力上限 | `AI_MAX_OUTPUT_TOKENS=800`、設定可能範囲1〜2000 |
| タイムアウト | 30秒 |
| 自動再試行 | なし |
| 二重実行 | 同じAPIプロセスの同じカードは分析中409 |
| 障害時 | キーやSDKの生エラーを返さず、CRUDは継続 |

アプリの回数制限は1つのローカルDB内だけの補助です。DB削除・設定変更・別ツールによるキー利用まで制限できません。全参加者の課金総額や利用期限は講師側のプロジェクト設定とキー管理で扱います。

## 当日の進行

- 第1回：環境差に備えて30分の調整枠を確保。起動できた人は見出し変更を先に進める。
- 第2回：1つの変更を小さく確認。画面の見た目だけでなく検索・空状態・スマートフォン幅も見る。
- 第3回：変更前にコミットとDBバックアップを取る。型・DB・API・UIの変更箇所を全員で対応付ける。
- 第4回：キーを画面共有せず設定。共通課題の比較は変更前後1回ずつを目安にする。AI障害時はモックで継続。
- 各回の最後に成果をコミットし、GitHubへpushしたことを確認する。
