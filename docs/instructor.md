# 講師向け準備

## 講座前

1. Windows / macOSの実機で、Node.js 24・Git・VS Code・Codexを準備する。
2. clone → `.env` 作成 → `npm install` → `npm run dev` を通して確認する。
3. 手動CRUD、AI生成、テーマ別・優先度別表示、ステータス変更、再起動後の保持を確認する。
4. `npm run check` と、講師が利用するキー・モデルでの実API接続を確認する。
5. APIの予算・レート制限・キーの利用期限はプラットフォーム側で準備する。
6. GitHubへ記録する手順を準備し、`.env` と `.local/` がGitの対象外であることを確認する。

アプリ側に日次利用制限、予算管理、トークン上限はありません。実APIに接続できない場合は、キーを空欄にして再起動するとサンプルで講義を進められます。

## 全4回の進め方

| 回 | テーマ | 共通課題・成果 |
| --- | --- | --- |
| 1 | 環境構築・Codex入門 | 起動、TODOの操作、構成の理解 |
| 2 | フロントエンド開発 | ダッシュボードの配色・カード・優先度表示の改造 |
| 3 | バックエンド開発 | 重要なTODOだけを取得・表示するAPIの追加 |
| 4 | オリジナルアプリ開発 | 仕様整理、実装計画、段階的な実装・検証・共有 |

各回の120分の配分は `docs/spec.md` と各回の資料に合わせます。第3回の追加課題は、最初から実装して配布しないようにしてください。既存の優先度別表示との違いを、API・SQLの処理から説明します。

## 初心者への説明

まず「操作 → 画面のstate → HTTP → API → DB」という一つの流れを追います。コードを一度にすべて理解することを求めず、改造したい箇所をCodexと探します。

Codexへの依頼は、目的・変えたい箇所・完成条件・確認方法を短く整理します。生成後は画面を自分で操作し、期待と違えば具体的に追加修正を依頼します。各回でGitの差分・コミット・pushを体験します。

## APIキーと対象範囲

キーはパスワードと同様に扱い、ソース・React・画面共有・チャットに含めないよう案内します。漏洩時はすぐに無効化・再発行します。講師がキーを配布する場合は管理方針を決め、安全な経路で渡してください。

講座の最初と最後に、成果物はローカルで動くアプリであり、インターネット公開・インフラ構築・本番運用は扱わないことを説明します。公開時には認証・認可、入力検証、脆弱性、機密情報、利用料金、データ保護などを別途検証する必要があります。AIが作ったコードにも検証が必要です。

終了時は仕様・実装計画とコードを記録し、秘密情報が含まれていないことを確認します。講座用キーの削除・失効は講師の配布方針に沿って行います。[検証記録](verification.md) の未確認範囲も配布前に確認してください。
