# AI Webアプリ開発ワークショップ カリキュラム要件（改訂版）

## 1. 講座の概要

プログラミング初心者を対象に、Codexを活用したWebアプリ開発を体験する。

全4回（各2時間、計8時間）で、開発環境の構築、フロントエンド・バックエンドの仕組み、既存アプリの改造、オリジナルアプリの仕様検討・実装を学ぶ。

共通のサンプルアプリとして「AI TODOプランナー」を使用する。

講座の目的は、Web開発技術の網羅的な習得ではなく、**AIを活用して自分のアイデアをWebアプリとして形にするための基本的な知識と開発プロセスを習得すること**である。

## 2. 講座で扱う範囲

- ローカル開発環境の構築
- Codexの基本操作
- AIを利用したアプリ開発の進め方
- フロントエンドの基本的な仕組み
- バックエンド・API・データベースの基本的な仕組み
- Codexを利用したUI変更・機能追加
- OpenAI APIを利用したAI機能の仕組み
- オリジナルアプリの仕様検討
- 実装計画の作成
- Codexによる実装・動作確認・修正
- Git / GitHubによるソースコード管理

開発したアプリはローカル環境で実行する。

## 3. 講座で扱わない範囲

本講座では、Webアプリをインターネット上に公開するためのインフラ構築や、本番環境での運用は扱わない。

具体的には、以下を対象外とする。

- クラウドサービスやサーバーの構築
- Webアプリのデプロイ
- ドメイン・DNSの設定
- HTTPS・SSL/TLS証明書の設定
- 本番環境のネットワーク設定
- 本番データベースの構築・運用
- CI/CDなどの自動デプロイ
- 公開環境での監視・バックアップ・障害対応
- 本番公開に必要なセキュリティ対策の設計・実装・検証

これらは実際のWebサービスを公開・運用するうえで重要な技術だが、本講座の対象範囲には含めない。

**講座の成果物は、ローカル環境で動作するWebアプリとする。**

なお、ローカル環境でアプリを実行する場合でも、Codex・GitHub・OpenAI APIの利用にはインターネット接続が必要となる。

## 4. セキュリティに関する基本方針

本講座では、本番運用を想定したセキュリティ対策の実装は扱わない。

ただし、AIを活用してアプリを開発する際に必要となる、基本的なセキュリティ上の注意事項について説明する。

### 4.1 OpenAI APIキーの取り扱い

OpenAI APIキーは、API利用権限に関わる機密情報である。

第三者に漏洩すると、意図しないAPI利用や料金の発生などにつながる可能性がある。

そのため、以下の点を説明する。

- APIキーはパスワードと同様に機密情報として管理する。
- APIキーをソースコードに直接記述しない。
- APIキーをReactなどのフロントエンドに埋め込まない。
- APIキーはバックエンド側の環境変数で管理する。
- `.env`ファイルをGitHubにアップロードしない。
- APIキーを第三者に共有したり、公開したりしない。
- APIキーが漏洩した場合は、速やかに無効化して再発行する。

サンプルアプリには、APIキーを適切に管理するための基本的な構成を用意する。

### 4.2 アプリの公開に関する注意

**ローカル環境で正常に動作するアプリが、そのまま安全に公開できるとは限らない。**

Codexが生成したコードについても、セキュリティが保証されるわけではない。

アプリをインターネット上に公開する場合は、少なくとも以下のような観点から、別途セキュリティ対策と検証が必要になることを説明する。

- 認証・認可の適切な実装
- APIへの不正アクセス対策
- 入力値の検証
- XSS・SQLインジェクションなどの脆弱性対策
- APIキーなどの機密情報の保護
- APIの呼び出し回数・利用料金の制限
- データの保護
- 利用ライブラリの脆弱性確認
- 本番環境の設定・運用上の安全性

これらの詳細な実装方法や検証手順は、本講座では扱わない。

受講者には、**AIでアプリを作れることと、安全なWebサービスとして公開・運用できることは別の能力である**と理解してもらう。

## 5. カリキュラム

### 第1回：環境構築・Codex入門

**テーマ：AIを使ったWebアプリ開発を始めよう**

目的：

開発環境を構築し、Codexの基本的な使い方を理解する。サンプルアプリを自分のPCで起動し、実際に操作する。

学習内容：

1. 講座の目的と全体構成
2. 講座で扱う範囲・扱わない範囲
3. アプリ公開とセキュリティに関する注意
4. VS Code・Node.js・Git・GitHubの準備
5. Codexの概要と基本操作
6. サンプルアプリの取得・起動
7. AI TODOプランナーの操作体験
8. Webアプリの全体構造の確認

ハンズオン：

- サンプルアプリを起動する。
- TODOを手動で登録・編集する。
- AIにやりたいことを伝えてTODOを生成する。
- テーマ別・優先度別にTODOを確認する。
- TODOのステータスを変更する。

時間配分：

| 内容 | 時間 |
|---|---:|
| 講座概要・対象範囲・セキュリティ上の注意 | 15分 |
| 開発環境の構築・確認 | 40分 |
| Codexの概要と基本操作 | 25分 |
| サンプルアプリの起動・操作 | 30分 |
| まとめ・質疑応答 | 10分 |
| **合計** | **120分** |

到達目標：

- 開発環境を構築できる。
- Codexの基本的な役割を理解できる。
- サンプルアプリをローカル環境で起動できる。
- 開発と公開の違いを理解できる。
- APIキーが機密情報であることを理解できる。

## 6. 講座終了時の説明

講座の最後に、以下の内容を改めて説明する。

### 6.1 本講座で学んだこと

- Codexを使ったアプリ開発
- フロントエンドの改造
- バックエンドの機能追加
- AIを使った仕様検討
- 仕様から実装までの開発プロセス

### 6.2 本講座で扱わなかったこと

- サーバーやクラウドなどのインフラ構築
- Webアプリのインターネット公開
- 本番環境の構築・運用
- 公開に必要なセキュリティ対策の実装・検証

### 6.3 今後アプリを公開する場合の注意

本講座で作成したアプリは、学習目的のローカルアプリである。

そのままインターネット上に公開することを想定していない。

公開する場合は、インフラの準備だけでなく、アプリケーションのセキュリティ検証が必要となる。

特にOpenAI APIキーなどの機密情報が漏洩しないように注意する。

また、Codexが生成したコードについても、適切なテストとセキュリティ検証を実施する必要がある。

**アプリが動作することと、安全に公開・運用できることは別である。**

この点を理解したうえで、講座終了後も開発を継続してもらう。

## 7. 最終到達目標

本講座の最終到達目標は、以下のとおりとする。

1. ローカル環境でWebアプリを起動できる。
2. Codexを使って既存アプリを改造できる。
3. フロントエンドの基本的な仕組みを理解できる。
4. バックエンド・API・DBの基本的な仕組みを理解できる。
5. Codexを使って新しい機能を追加できる。
6. 作りたいアプリの仕様を整理できる。
7. 仕様をもとに実装計画を作成できる。
8. Codexを使ってオリジナルアプリの実装を進められる。
9. APIキーなどの機密情報を適切に取り扱う必要性を理解できる。
10. ローカル開発と本番公開の違い、および公開前のセキュリティ検証の重要性を理解できる。

**最終成果物：ローカル環境で動作するWebアプリと、その仕様・実装計画。**

本講座は、受講者がCodexを使ってWebアプリを開発する第一歩を踏み出すための講座として位置付ける。
