# 検証記録

2026-11-08に、AI TODOプランナーへの書き換え後の実装を確認しました。

## 自動確認

`npm run check`（型チェック・画面ビルド・自動テスト14件）が成功しました。

- TODOの登録・一覧取得・編集・ステータス変更・削除。
- 必須項目・選択肢・JSON形式の確認、未入力の説明の許可。
- サンプルと偽のAI応答によるTODOの生成・保存。
- 入力ごとに要約テーマを1つ作り、その回の全TODOへ共通テーマを保存すること。
- AI失敗時に追加せず、内部例外やキーを応答へ含めないこと。
- 残高不足・利用枠不足・認証エラーを区別して案内すること。
- 文字数・生成件数・利用回数にアプリ独自の上限がないこと。
- DBを再度開いた後も編集・削除が保持されること。
- 既存のideas・cardsテーブルと内容を保持してtodosを追加すること。
- 複数件の保存失敗時に全件ロールバックすること。
- キーの有無だけで実APIとサンプルを選ぶこと。
- Responses APIへJSON Schemaを送り、独自トークン上限を渡さないこと。
- 空・未完了・拒否の応答を成功とせず、失敗時に自動再試行しないこと。

自動テストはメモリー上または一時フォルダーのSQLite、偽のAIサービス、SDKへの偽fetchを使います。実APIは呼びません。

## 初回インストールとブラウザー

既存のnode_modules・DB・.envを含まない一時コピーを作り、`.env.example` のコピー → `npm install` → `npm run check` が成功しました。

そのコピーを `npm run dev` で起動し、ブラウザーで以下を確認しました。

- 空の一覧からTODOを手動登録し、説明・ステータスを編集。
- カードから完了へ変更し、ステータスで絞り込み。
- サンプルTODOを生成し、テーマ別・優先度別に表示。
- 再読み込み後も同じTODOが表示されること。
- AIと保存の失敗応答をブラウザーで偽装し、エラー表示と入力保持を確認。
- 編集中のTODOを削除した場合に、編集フォームも閉じること。
- 1440px幅と390px幅で表示し、390px幅で横にはみ出さず登録できること。
- Tabキーでフォーカスを移動でき、JavaScriptの実行エラーがないこと。
- 停止後に `npm start` へ切り替えて、ビルド済み画面・アセット・APIを配信し、同じ一時DBのTODOを表示できること。
- 未定義のAPIが404になること。

既存の開発サーバーと競合しないよう、確認用コピーだけAPIを3187番、画面を5187番に変更しました。リポジトリの既定値は3000番・5173番です。確認用に起動したサーバーは停止しました。

資料の相対リンク、全4回の時間配分、`git diff --check` も確認しました。
