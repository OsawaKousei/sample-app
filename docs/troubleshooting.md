# トラブルシューティング

## Node.js・npmが見つからない

Node.js 24.13以降の24系をインストールし、VS Codeとターミナルを開き直します。`node --version` と `npm --version` を確認してください。

WindowsのPowerShellで `npm.ps1` がブロックされる場合は、`npm.cmd install` / `npm.cmd run dev` を使うか、ターミナルをコマンドプロンプトに切り替えます。

## 起動できない

ルートの `package.json` がある場所で `npm install` → `npm run dev` を実行します。別のOSから `node_modules` をコピーせず、そのPCでインストールしてください。依存を入れ直す場合はサーバーを停止して `npm ci` を使えます。DBの削除は不要です。

## ポートが使用中

前に起動した開発サーバーを `Ctrl+C` で止めます。このアプリは画面に5173番、APIに3000番を使います。同時に複数起動しないでください。

## TODOを読み書きできない

ターミナルのAPIの起動表示を確認します。http://127.0.0.1:3000/healthz と http://127.0.0.1:5173/healthz がどちらも `{"status":"ok"}` を返せば画面からAPIまで接続できています。APIを起動してからページを再読み込みしてください。

保存先の `.local/` の書き込み権限とディスク容量も確認します。OneDriveなどの同期フォルダーは避けます。バックアップはサーバーを停止して `.local/` フォルダー全体をコピーしてください。

## サンプルTODOが生成される

ルートの `.env` に `OPENAI_API_KEY` を設定して、サーバーを再起動します。キーが空欄のときだけサンプルを使います。モード設定はありません。

## AIがエラーになる

キー・モデル名・ネットワーク・プラットフォームの利用設定を確認してください。`OPENAI_MODEL` にはJSON Schema形式の出力に対応した、利用権限のあるモデルを設定します。アプリ独自の回数・予算・トークン数制限はありません。

失敗した処理からTODOは追加されず、入力は画面に残ります。手動のTODO操作は続けられます。サンプルを使いたい場合は、キーを空欄にして再起動してください。

## .envの変更が反映されない

`Ctrl+C` で停止し、`npm run dev` を再実行します。OS側に同名の環境変数がある場合はそちらが優先されます。キーの値を確認のためにログへ出さないでください。

## 旧版の相談・カードが見えない

今回の画面はTODO用です。旧版の `ideas`・`cards` テーブルと内容は、同じ `.local/idea-board.sqlite` 内に保持しています。DBを消さないでください。旧データをTODOへ変換したい場合は、バックアップを取り、項目の対応を決めてから別途移行します。

## キーを公開してしまった

講師に連絡し、プラットフォームでキーを無効化・再発行してください。GitHubからファイルを消すだけでは、漏洩したキーは無効になりません。`.env` をGitHubやチャットへ貼り付けないでください。
