# トラブルシューティング

まず、`package.json` があるリポジトリのルートで実行しているか確認します。講師にはOS、`node --version`、実行コマンド、秘密情報を除いたエラーを伝えます。

## node / npm / git が見つからない

インストール後にターミナルとVS Codeを開き直します。Node.jsは24.13以降の24系を使用します。Windowsで `npm.ps1` がブロックされる場合は `npm.cmd` を使うかコマンドプロンプトに切り替えます。

## npm install に失敗する

ネットワーク・プロキシ・ディスク容量を確認し、ルートから再実行します。`npm ci` はロックファイルに合わせて依存を入れ直すコマンドです。起動中のサーバーを停止してから使います。

```sh
npm ci
```

`EBADENGINE`、`node:sqlite` が見つからない、TypeScriptを実行できない場合はNode.jsのバージョンが合っていない可能性があります。24系に切り替えて再実行します。`node:sqlite` に関する実験的機能の警告だけで処理が続いている場合は起動エラーとは別です。

## 5173 / 3000番が使用中

ほかのターミナルの `npm run dev` やDockerコンテナを停止します。この教材はViteのポート自動変更を無効にしているため、競合時は明示的に失敗します。開発サーバーを二重に起動しないでください。

APIポートだけ変更する場合、`.env` の `PORT=3001` と、Vite設定のプロキシを一致させます。

```sh
# macOS / Linux
API_PROXY_TARGET=http://127.0.0.1:3001 npm run dev
```

```powershell
# PowerShell
$env:API_PROXY_TARGET="http://127.0.0.1:3001"
npm run dev
```

Viteは `.env` を読まないため、`API_PROXY_TARGET` は起動するシェルで設定します。Composeは内部の3000番を前提にしているので、まず既定ポートの競合を解消してください。

## 「ボードを読み込めませんでした」

1. ターミナルにAPIの起動ログがあるか確認。
2. http://127.0.0.1:3000/healthz を開き、`{"status":"ok"}` が出るか確認。
3. http://127.0.0.1:5173/healthz も同様に確認。後者だけ失敗するならViteのプロキシ設定を確認。
4. コンソールを確認し、「再読み込み」を押す。

## 保存後にカードが見えない

検索語・カテゴリ・ステータスで非表示になっている可能性があります。「絞り込みをクリア」を押します。変更したカードが別の条件に移った場合も、保存データは残っています。

## `.env` を変更しても反映されない

`.env` は起動時に読み込みます。`Ctrl+C` → `npm run dev` で再起動します。Composeなら `docker compose restart api`。OS側ですでに設定された同名の環境変数は `.env` より優先します。

`setup:local` は既存 `.env` を保護するため追記しません。古い設定しかない場合は `.env.example` と比較し、必要な変数を手で追加します。キーの値を共有しないでください。

## AIのボタンが押せない

- 新しいカードは最初に保存します。
- 編集中の内容を保存し、カードを開き直します。
- AI未設定なら `.env` に `AI_MODE=mock` を設定して再起動します。
- 実APIでは `AI_MODE=openai` と `OPENAI_API_KEY` の両方が必要です。

## AIが接続エラーになる

キーの有効性・講師指定モデル・ネットワーク・利用枠を確認します。AI障害でもカードは残り、CRUDは使えます。待機は最大30秒で、自動再試行はしません。講師に相談し、必要なら `AI_MODE=mock` に戻して進めます。未完了または空のAI応答も失敗として扱い、以前の結果を残します。

## 日次上限に達した

実APIの試行回数は失敗も含み、1つのDBごとに保存します。再起動しても戻りません。リセットはUTC 0時（日本時間9時）です。講師に確認してから次の実API利用を判断し、練習はモックで続けます。DBを削除して制限を回避しないでください。

## DBに書き込めない / locked

`.local/` の書き込み権限、ディスク容量、同期ソフトを確認します。npm直接起動とComposeが同じDBを同時に使わないよう停止します。LinuxのDockerでは `npm run setup:local` 後、`--env-file .env.compose` 付きで起動します。

バックアップはAPIを停止し、`.local/` フォルダ全体をコピーします。SQLiteの `-wal` / `-shm` が残っていれば一緒に扱います。

## 練習データを初期化したい

この操作では保存カードとAI試行回数を手放すため、実APIの利用中は行いません。講師の案内で `AI_MODE=mock` に戻し、サーバーを停止してから `.local` フォルダを別名に移動して保管します。次の起動で新しいDBと6枚のサンプルが作られます。

## Composeの権限エラー

Docker Desktop / Docker Engineを起動し、`docker compose version` を確認します。LinuxのDockerソケット権限や社用PCの管理制限は管理者に相談し、講義では通常のnpm起動を使えます。WindowsはLinuxコンテナで実行します。

## 間違ってキーをGitHubに載せた

まず講師に連絡し、そのキーを失効します。ファイルを消すだけでは履歴のキーは消えません。キーの値をチャットや課題提出に貼らず、講師と履歴の対応を進めます。
